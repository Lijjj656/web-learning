# 第 17 节：把任务保存到 MySQL

## 为什么要做这一步

现在 Vue 里的 `tasks` 是一个 JavaScript 数组。新增、删除、改状态只存在当前页面内，刷新后就恢复初始数据。真正的学习系统需要把任务写入数据库，换电脑或重新打开页面后仍能读取。

这一步还要解决“用户只能看到自己的任务”：任务表增加 `user_id`，后端从 JWT token 得到当前用户，再用 `user_id` 查询和写入任务。前端传来的 `user_id` 不可信，不能让用户自己指定归属。

```text
Vue tasks 页面
    ↓ 带 Authorization: Bearer token
Spring Boot TaskController
    ↓ 从 token 得到当前用户 id
TaskService / MyBatis Mapper
    ↓ SQL 查询 WHERE user_id = 当前用户 id
MySQL tasks 表
```

## 任务表的字段

| 字段 | 作用 |
|---|---|
| `id` | 任务编号，主键 |
| `user_id` | 所属用户，对应 `users.id` |
| `title` | 任务名称 |
| `category` | 分类，例如 Web、Java |
| `priority` | 优先级，例如 普通、高 |
| `status` | 状态：未开始、进行中、已完成 |
| `created_at` | 创建时间 |

用户信息和任务信息分开保存：`users` 是账号档案，`tasks` 是学习记录。`user_id` 是两张表之间的关系。

## 这一节要学会

- 前端数组和数据库记录的区别。
- JWT 负责确认“当前是谁”，`user_id` 负责筛选“他的任务”。
- 每个任务接口都要检查 token，并在 SQL 中限制当前用户。
- 数据库表结构先设计好，再写 Java 实体、Mapper、Service 和 Controller。

## 直接参考的讲解

**为什么刷新不丢任务？** Vue 数组只负责显示；新增先发送 POST 请求，后端将记录写入 MySQL。刷新后 Vue 再 GET 查询，从数据库重建数组。因此清空页面内存不会清空数据库。

**为什么用户 B 看不到用户 A 的任务？** 后端验证 B 的 token，得到 B 的用户 ID，再执行带 `WHERE user_id = B的ID` 的 SQL。修改和删除同时检查任务编号与归属。隐藏前端按钮不能替代这项后端检查。

**点击创建后发生什么？** 弹窗收集输入 → Vue 带 token 发 POST → Controller 校验参数 → Service 确认用户 → Mapper 执行 INSERT → MySQL 返回任务编号 → 页面重新加载任务和统计。

**新账号为什么是空列表？** 每个账号只读取自己的数据库记录。原先页面写死的三条示例记录没有进入数据库。

## 遇到的问题与处理

- PowerShell 传中文 SQL 默认值时出现编码问题：建表脚本改为不包含中文默认值，由应用明确传入优先级和状态。
- 删除请求异常曾被当作取消弹窗：已把弹窗取消与接口失败分别处理，服务失败会显示错误。
- 本机 Java 启动器会产生子进程：重启测试使用实际 Java 可执行文件，并验证端口释放及进程 ID 变化。
- 后端无凭证请求已统一返回 401；标题和可选值由后端校验。
