## 先看完整流程

```text
弹窗输入
  ↓ newTask.value
Vue createTask()
  ↓ POST /api/tasks + JSON + JWT
TaskController.create()
  ↓ @RequestBody 转成 TaskRequest，@Valid 校验
TaskService.create()
  ↓ 从 JWT 得到 userId，组装 Task
TaskMapper.insert()
  ↓ INSERT INTO tasks
MySQL tasks 表
```

成功后，前端重新请求任务列表和统计，所以页面显示的是数据库中的最新结果。

## 两层校验为什么都要有

前端校验让用户马上看到提示，体验更好；后端校验才是真正的安全边界，因为任何人都可以绕过网页直接调用接口。

`TaskRequest` 当前规则：

- `title` 不能为空，最长 200 个字符。
- `category` 只能是 `Web`、`Java` 或 `AI`。
- `priority` 只能是 `普通` 或 `高`。
- `status` 只能是 `未开始`、`进行中` 或 `已完成`。

`@Valid` 触发校验，错误由统一异常处理返回 400。Service 不从请求中读取 `userId`，而是从已经验证的 JWT 得到当前用户，避免用户伪造归属。

## 直接参考的讲解

“新增时，Vue 从弹窗模型读取标题等字段，发送 POST 请求。Controller 用 `@RequestBody` 接收 JSON，用 `@Valid` 触发 `TaskRequest` 校验。Service 验证 JWT 得到当前用户 ID，把用户 ID 和请求字段组装成 Task。Mapper 执行 INSERT，数据库保存记录。前端重新查询，所以刷新后仍能看到。”

## 今天的复习重点

`GET` 是查询，`POST` 是创建；`@RequestBody` 读取请求体，`@Valid` 检查输入，`Authorization` 说明当前是谁。`user_id` 不由前端决定，而由后端从 token 得到。
