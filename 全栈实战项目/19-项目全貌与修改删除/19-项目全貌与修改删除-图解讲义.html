1. 我们为什么要写这个系统？

先想一个实际场景：你有“复习 Java”“练习 Vue”两条任务。今天记录进度，明天打开电脑，还想看到这些任务；换一个账号，则应该看到另一个人的学习记录。

一个完整任务至少有三个阶段：记录下来 → 跟踪进度 → 查看结果。因此我们需要创建、查询、修改、删除和统计。这些操作统称增删改查，常写作 CRUD。

你想做什么网页怎么做后端怎么接收数据库做什么
查看自己的任务打开任务管理页GET /api/tasksSELECT：读取记录
添加学习计划新建弹窗填写并创建POST /api/tasksINSERT：新增一行
修改内容或进度编辑弹窗或状态下拉框PUT /api/tasks/任务编号UPDATE：改变已有行
移除不需要的计划删除并确认DELETE /api/tasks/任务编号DELETE：删除指定行
查看完成情况打开学习统计GET /api/tasks/statsCOUNT、SUM：按当前用户计算数量

为什么只改网页数组不够？

网页中的 tasks 数组可以临时显示任务。但刷新网页会重新运行页面代码，临时数组不能代替持久保存。MySQL 负责长期保存，网页每次加载时从后端重新查询记录。

同样，只在网页上把状态显示为“已完成”也不够：数据库不变，重新读取时仍是“未开始”。今天写 UPDATE，就是让这次进度变化真正保存下来。

每一段代码都服务于一个用户动作。学 SQL 时先想“我希望哪条记录发生什么变化”，再决定使用 SELECT、INSERT、UPDATE 还是 DELETE。

修改的验收

编辑名称、分类或优先级；改变状态；刷新后仍保留。任务总数不变，完成数量随状态变化。

删除的验收

确认删除后记录消失，刷新不会回来，统计同步减少。别人不能靠改任务编号删掉你的记录。

取消删除弹窗时，没有发送删除请求。确认以后，后端成功删除，页面才显示成功。本项目直接移除数据库记录，没有回收站功能。

信息解决的问题从哪里得到

6.1 前端：把用户动作变成请求

// 状态变化时的请求摘录
await apiRequest(`/api/tasks/${task.id}`, {
    method: "PUT",
    body: JSON.stringify({
        title: task.title,
        category: task.category,
        priority: task.priority,
        status: task.status,
    }),
});

这里传完整可编辑字段，因为当前 PUT 接口会更新这些字段。只发送 status 的片段适合教学说明，不能直接替换正式请求；否则其他必填字段缺失会导致 400。请求头由 apiRequest 加入 token。

6.2 Controller：读取地址、内容和凭证

@PutMapping("/{id}")
public TaskResponse update(
    @PathVariable Long id,
    @Valid @RequestBody TaskRequest request,
    @RequestHeader(value = "Authorization", required = false)
    String authorization) {
    return service.update(id, request, authorization);
}

@PathVariable 从地址取任务编号；@RequestBody 从 JSON 取新内容；@Valid 触发输入规则；@RequestHeader 取凭证。允许请求头为空是为了由 Service 统一返回 401，不代表允许匿名修改。

6.3 Service：确认用户，组装要修改的数据

public TaskResponse update(Long id, TaskRequest request,
                           String authorization) {
    Long userId = currentUserId(authorization);
    Task task = new Task();
    task.setId(id);
    task.setUserId(userId);
    task.setTitle(request.title().trim());
    task.setCategory(request.category().trim());
    task.setPriority(request.priority().trim());
    task.setStatus(request.status().trim());
    if (mapper.update(task) == 0) throw notFound();
    return TaskResponse.from(requireOwned(id, userId));
}

你已经练过创建对象和 set 方法。修改比新增多了 task.setId(id)，因为新增由数据库生成编号，修改需要指定已有记录。mapper.update 返回受影响行数；本项目配置下，没有匹配到可修改任务时返回 0，Service 返回 404。更新后再查询并转换为给前端的响应对象。

6.4 Mapper 与 SQL：Java 方法对应数据库操作

// TaskMapper.java
int update(Task task);

// TaskMapper.xml 对应的 SQL
UPDATE tasks
SET title = #{title}, category = #{category},
    priority = #{priority}, status = #{status}
WHERE id = #{id} AND user_id = #{userId}

MyBatis 根据 Mapper 命名空间和 XML 的 id="update" 找到 SQL，读取 Task 的属性并绑定参数。#{...} 是参数绑定占位符，不能去掉花括号当普通 SQL 名称使用。

数据库中的 user_id 与 Java 属性 userId 名字不同，但表示同一个任务归属。SET 指定“改什么”，WHERE 指定“允许改哪条”。

7. 为什么修改和删除都要检查归属？

前端表格只显示自己的任务，但请求地址可以被人为修改。服务器不能因为“按钮在网页里”就相信请求一定合法。

图 4：任务编号确定目标，用户编号确定权限；AND 表示两个条件同时成立。

删除沿用相同的归属规则

// Service：身份从 token 得到
public void delete(Long id, String authorization) {
    Long userId = currentUserId(authorization);
    if (mapper.delete(id, userId) == 0) throw notFound();
}

// SQL：只删除属于当前用户的指定任务
DELETE FROM tasks
WHERE id = #{id} AND user_id = #{userId}

删除不需要新的 title 或 status，因此不必组装完整 TaskRequest。它只需要“删哪条”和“当前是谁”。前端取消确认时不发请求，确认后发送 DELETE，成功返回 204，没有 JSON 响应体。

接口对“不存在的任务”和“属于别人的任务”统一返回 404，避免透露其他用户的任务是否存在。缺少或失效 token 则返回 401；这两个错误原因不同。

后续网页还会怎么变？
