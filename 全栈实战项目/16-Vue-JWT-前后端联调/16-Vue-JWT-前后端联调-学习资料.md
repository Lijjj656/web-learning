# Vue 与 JWT 后端联调

## 先说结论：Vue + JWT 是什么

Vue 是浏览器里的界面：显示登录表单、接收输入、发送请求、展示返回的用户信息。JWT（JSON Web Token）是一种登录凭证格式：后端核对账号密码后签发一个有有效期的 token，前端在后续请求中带上它，后端验证签名和有效期，判断请求者是谁。

这一节的主要功能是**注册、登录、保持当前标签页的登录状态、读取当前用户、退出登录**。它把前端页面和 Spring Boot 身份验证接口接成一个完整流程。JWT 不负责保存用户或任务；MySQL 保存用户，当前任务表仍只是前端 Demo 数据。

可以把 token 理解为一张有期限、可验证的“通行证”：登录时用密码换取它；以后请求受保护接口时出示它。这个比喻只帮助理解，不代表 token 可以随意公开。拿到有效 token 的人可能在过期前以你的身份发请求，因此不要把完整 token 发到聊天或截图中。

```text
浏览器里的 Vue 页面              Spring Boot 后端                 MySQL
填写邮箱和密码 ── POST /login ──> 校验密码 ──────────────────> 查询用户
保存返回的 token <─────────────── 签发 token <───────────────────┘
携带 Bearer token ── GET /me ───> 验证 token、查询用户 ───────> 查询用户
显示姓名和邮箱 <────────────────── 返回用户信息 <────────────────┘
```

页面“登录后才显示任务”只是前端界面控制；真正的访问保护必须由后端验证 token。自己隐藏按钮或改 Vue 代码，不能代替后端鉴权。

## 这节把什么连起来

- Vue + Element Plus 页面运行在 `http://localhost:5173/`。
- Spring Boot JWT API 运行在 `http://localhost:8084/`。
- MySQL 保存注册用户；这个页面里的任务仍是前端 Demo 数据，刷新后会恢复初始三项。

## 登录流程

1. 登录表单把邮箱和密码发送给 `POST /api/auth/login`；注册表单把姓名、邮箱和密码发送给 `POST /api/auth/register`。
2. 后端核对 MySQL 中的用户和密码哈希，成功后返回 JWT `token`。
3. 前端用 `Authorization: Bearer <token>` 请求 `GET /api/auth/me`。
4. 后端验证 token，返回当前用户的编号、姓名和邮箱。前端收到用户信息后才显示任务页面。
5. 点击退出登录会清除本标签页保存的 token，再回到登录表单。

`vite.config.js` 把开发环境的 `/api` 请求代理到 8084，所以前端代码只写 `/api/auth/login` 等路径。这个代理只在 Vite 开发服务中生效；正式部署需要另外配置同源反向代理或 API 地址。

## 三种常见错误

- `401`：邮箱或密码错误，或已有 token 无效/过期。
- `500`：后端处理失败；看运行 Spring Boot 的 PowerShell 窗口日志。
- 无法连接服务：确认 5173 和 8084 两个服务都在运行。单独打开 `localhost:8084` 出现首页 `404` 不代表登录接口不可用。

## 数据保存在哪里

这次用 `sessionStorage` 保存 token：同一浏览器标签页刷新后可恢复登录，关闭该标签页后会话结束。不要把真实密码或完整 token 写进代码、截图或聊天。个人设置的“本机名称”仍保存在 `localStorage`，它不修改 MySQL 中的账号姓名。

## 自测顺序

1. 保持后端和 Vite 两个窗口运行，刷新 `http://localhost:5173/`，应看到“登录 / 注册”页签。
2. 用已有账号登录，或在“注册”中填写新姓名、未用过的邮箱和自己设置的密码；成功后应看到任务管理及右上角账号姓名。
3. 打开“个人设置”，应看到后端返回的姓名和邮箱；刷新页面，应仍保持登录。
4. 点击右上角退出图标，应返回登录表单；输入错误密码应显示错误提示。

## 忘记旧账号密码时

MySQL 中保存的是 BCrypt 密码哈希，不是可以读回的明文密码；此 Demo 没有“重置密码”接口。注册页签会创建一个**新账号**，不会找回、修改或删除旧账号。注册时使用未注册过的邮箱，并自行保管新密码。不要把密码或完整 token 发到聊天里。
