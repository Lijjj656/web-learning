## 三种前端技术各自负责什么

| 技术 | 作用 | 例子 |
|---|---|---|
| HTML | 页面结构和内容 | 标题、表格、表单 |
| CSS | 页面样式和布局 | 颜色、间距、登录页布局 |
| JavaScript | 页面交互和数据处理 | 点击按钮、Todo List、调用后端 API |

HTML 是网页的骨架。现在先学会正确组织内容，后续 CSS 负责美化，JavaScript 负责让页面“动起来”。

## 重点一：页面结构和标题层级

```html
<main>
  <section id="about">
    <h2>关于我</h2>
    <h3>我的技能</h3>
  </section>
</main>
```

- `main`：页面最主要的内容区域。
- `section`：一个主题明确的区域，这里是“关于我”。
- `h2`：区域的主要标题。
- `h3`：该区域内部的小标题。

“我的技能”属于“关于我”的一部分，不和“学习项目”“联系我”并列，所以使用 `h3`，而不是再使用 `h2`。

## 重点二：页面内导航

```html
<a href="#contact">联系方式</a>

<section id="contact">
  <h2>联系我</h2>
</section>
```

`href="#contact"` 的 `#contact` 会寻找页面里 `id="contact"` 的元素。两者名称一致，点击链接时浏览器就会跳到“联系我”区域。

记忆方法：`href` 是“要去哪里”，`id` 是“这个位置叫什么名字”。

## 重点三：表格

```html
<tr>
  <th>技术</th>
  <th>阶段</th>
  <th>下一步</th>
</tr>
<tr>
  <td>HTML</td>
  <td>进行中</td>
  <td>完成页面结构练习</td>
</tr>
```

- `tr`：一整行。
- `th`：表头单元格，说明这一列的含义。
- `td`：普通数据单元格，存放实际数据。
- `thead`：表头部分。
- `tbody`：数据部分。

表格用于展示行列关系明确的数据，例如学习进度、任务清单、订单列表。它不用于做页面布局。

## 重点四：label、for、id、name

```html
<label for="phone">手机号</label>
<input id="phone" name="phone" type="tel" />
```

这四部分的含义不同：

- `label`：输入框的文字说明。
- `for="phone"`：说明这个文字对应名为 `phone` 的输入框。
- `id="phone"`：输入框在当前页面中的唯一标识。
- `name="phone"`：未来向后端提交数据时使用的字段名。
- `type="tel"`：告诉浏览器这里适合输入电话。

`for` 和 `id` 必须相同。这样浏览器就知道“手机号”是哪个输入框的说明；点击“手机号”文字时，光标也会进入对应输入框。

将来提交后端时，数据可能类似：

```json
{
  "name": "张三",
  "email": "zhangsan@example.com",
  "phone": "13800138000"
}
```

其中的 `phone` 就来自 `name="phone"`。

## 重点五：为什么现在不能保存到 MySQL

当前 HTML 能做到：显示表单、让用户输入、检查必填项和邮箱格式。

例如：

```html
<input id="email" name="email" type="email" required />
```

- `required`：不能为空。
- `type="email"`：浏览器会做基础邮箱格式检查。

但 HTML 本身不能保存数据库。完整流程还需要：

```text
用户填写表单
→ JavaScript 读取表单数据
→ JavaScript 发送 HTTP 请求
→ Spring Boot 接收请求并校验
→ Spring Boot 执行 SQL
→ MySQL 保存数据
→ Spring Boot 返回结果
→ JavaScript 在页面显示“保存成功”
```

当前 Demo 只完成第一步：设计用户可以输入哪些数据。这是后续 JavaScript、Spring Boot 和 MySQL 学习的基础。
